# nl2shell · 基于大语言模型的智能 Shell 系统

面向不熟悉 Linux 命令的用户。用户说明目标，Ollama 理解条件、询问信息并生成操作计划。程序检查计划，显示实际文件清单，获得确认后执行，并检查结果。

## 大模型的作用

- 理解文件类型、时间、大小、路径和查找范围。
- 发现缺失条件，并提出一个具体问题。
- 将目标拆成最多三个步骤。
- 用中文解释方案。
- 根据只读计划生成候选命令参数数组。程序检查后才允许执行。

只读命令经过“结构化计划 → 独立需求契约对照 → 模型候选参数数组 → 程序审查 → 确认 → 原生命令执行 → 独立结果检查”。程序不会执行任意模型字符串，不使用 Shell 解释候选命令。文件写操作继续由 Python 固定工具执行。

程序在规划阶段检查路径边界，并把文件路径统一为工作目录内的相对路径。复制或移动目标、修改时间范围需要能对应到用户原话或补充回答；缺少证据时返回追问。目标表达检查采用保守规则，不是通用语言理解器，未识别的表达需要补充说明。

核心动作主要由独立的模型调用先识别为结构化意图，再交给规划器。程序检查必要操作是否全部出现，并拒绝额外写操作；对于完整、无歧义且符合受支持语法的请求，有限的确定性规则可以恢复模型误判，不能识别的表达仍需澄清或停止。任务历史保留脱敏后的意图和计划尝试，包括原始输出、校验错误及已发生的恢复说明。意图识别本身仍可能出错，不能据此保证所有自然语言请求正确；写入前仍显示实际文件和操作并要求确认。

Intent 会复核动作是否明确及否定要求。明确命名的文件且无需筛选时，使用直接文件操作；可证明只查询该文件的冗余查找可移除，其他查找不能擅自替换。拒绝原因使用 reason_code 分类后由程序生成文字。仅复测当前三条边界请求可运行 `python eval/intent_boundary.py`。

模型重试后仍遗漏复制步骤时，仅对一个已验证的当前目录查找步骤进行有限恢复：用户必须明确给出唯一复制目标，明确时间也必须与查找参数一致。程序追加引用该查找结果的复制步骤，重新检查计划，并在评测记录中标明恢复。不修复越界、模糊目标或错误查找范围；仍需要用户确认后执行。

## 第一版支持范围

查找、计数、创建空文件及目录、复制、移动、重命名、按文件类型整理、条件备份、回收和恢复。支持查询磁盘、内存和系统信息。

新增 NL2Bash 原生执行只支持 Ubuntu/WSL。命令及获准参数如下；其他参数组合拒绝执行。

| 命令 | 参数规则与验证 |
| --- | --- |
| `pwd` | `-P`；输出必须等于实际工作目录 |
| `ls` | `-1 --color=never --quoting-style=literal`，可按计划加 `-A`，`-- 路径`；核对实际当前层名称 |
| `find` | 固定起点、`-mindepth 1`，非递归必须 `-maxdepth 1`，仅 `-type f`；按计划加文件名、精确时间界限、字节大小条件；排除敏感路径；`-print0` 输出逐项核对；禁止 `-exec`、`-delete` 等其他动作 |
| `grep` | `-F -n -e 字面文本 -- 文件`；大小写敏感；逐行比对；退出码 1 单独记为无匹配 |
| `wc` | `-l`、`-w` 或 `-c` 中一个，`-- 文件`；使用 C.UTF-8，独立计算行数、普通空白分隔单词数或 UTF-8 字节数；不做中文分词；单词统计不接受特殊 Unicode 空白及控制字符 |
| `head` / `tail` | `-n 明确行数 -- 文件`，1 至 1000 行；逐字核对首尾文本 |
| `stat` | `-c %i -- 普通文件`；仅查询 inode，由 Python 文件状态接口独立核对，不读取内容 |
| `df` | `-B1 --output=size,used,avail -- 工作区路径`；核对实际文件系统总量和数值范围 |
| `free` | `-b`；核对 `/proc/meminfo` 内存总量和数值范围，瞬时字段不作逐字静态比对 |
| `uname` | `-s -r -m`；核对系统名、内核版本、架构 |

候选使用 JSON 参数数组。中文、空格和引号保持在单个参数中，文件路径加 `./` 或使用 `.`，前导短横线不会变成选项。展示文本由参数数组生成；实际执行记录包含系统命令的绝对路径和原候选参数，不静默换用另一条命令。

文本查询限单个、不超过 1 MiB 的普通 UTF-8 文件。常见凭据路径、检测出的凭据文本、符号链接、硬链接、设备和审计记录拒绝读取；检测不能识别所有敏感信息。文件查找排除敏感目录及文件。名称中含换行、递归文本搜索、正则搜索均暂不支持。

inode 查询只读取普通文件元数据，不受文本编码和大小限制，仍拒绝敏感路径、链接、特殊文件和审计记录。

只读查询与文件写入请分别提交。用于备份等写操作的查找步骤仍由受保护的 Python 工具完成，不能描述为模型 Bash 实际执行。文件数量任务执行 `find` 后由程序核验并计数，不使用管道。查询无匹配、命令失败、输出截断和已验证完成分别记录；退出码 0 不直接记为任务完成。

软件安装、权限修改、服务管理、网络操作、任意脚本和永久删除均不支持。旧的自由命令输出会被拒绝，不会自动转换或执行。

## Linux 快速开始

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
ollama pull qwen2.5-coder:7b
python cli.py
```

Ollama 需先安装。若服务尚未启动，在另一个终端运行 `ollama serve`，并保持它运行。默认使用 `http://localhost:11434/v1` 和 `qwen2.5-coder:7b`。可通过 `.env` 修改模型地址和名称。DeepSeek 接口继续保留，但第一版主验收路径为本地 Ollama。

启动时，当前目录就是工作目录。建议先用专用测试目录，或在交互中输入 `/workspace /path/to/test-directory`。

```text
找出当前目录这一层最近七天修改、超过 10 MB 的 PDF
列出当前目录的内容，包括隐藏文件
在 note.txt 中搜索字面文本“错误”
统计 note.txt 的行数
查看 note.txt 的前五行
显示 note.txt 的 inode
帮我整理一下这个目录
备份当前目录及子目录最近七天修改的 Python 文件到 backup，保留目录结构
```

## 文件保护

- 所有文件路径必须位于工作目录内。第一版拒绝符号链接和特殊文件。
- 执行前显示操作及实际源、目标路径。需要完整输入 `yes`。
- 同名文件加编号，例如 `report_1.txt`。创建空文件也不清空已有内容。
- 确认后再次检查文件事实。发生变化时重新确认。
- 删除进入 `.nl2shell-trash`，不自动清空。使用 `/trash` 查看，用 `/restore 编号` 恢复。
- 失败时停止后续步骤。已完成操作保留，并逐项报告。跨文件系统移动明确失败。
- 模型不能自行选择验证命令。复制和备份比较文件内容，移动和恢复检查源、目标位置。

确认预览会读取文件内容计算摘要，大目录可能较慢。不要在运行期间由其他程序反复修改同一组文件。工作区规则不是操作系统沙箱；应在可信的个人工作目录运行。

## 常用入口

```bash
python cli.py --preview "统计当前目录下的 Python 文件"
python cli.py --json --preview "找出当前目录这一层的 PDF"
python cli.py --json --yes "查看系统信息"
python cli.py --batch tasks.jsonl
```

`--yes` 只允许受支持的只读任务跳过确认。JSON 模式不交互：缺信息时返回 `needs_clarification`，文件修改返回 `cancelled`。批处理只执行只读任务。旧 `auto-safe` 设置仍可读取，但交互操作仍逐次确认。

旧 Docker 执行接口保留用于隔离测试。新增 NL2Bash 参数数组入口不支持 Docker，选择该后端时明确停止，不降级到主机执行。本机写操作仍被 Docker 后端拒绝。

## 错误诊断与一次受控修复

CLI 根据实际退出码、错误输出、超时、操作阶段与文件状态进行确定性分类，直接显示程序生成的原因和检查建议，不为解释错误额外调用模型。模型产生的文字不能覆盖程序记录的执行事实，也不能作为执行指令。

成功、无匹配、失败、超时、已执行但未验证、用户取消和安全拒绝分别处理。无匹配不是需要修复的错误。缺文件、权限不足、参数不兼容、超时和无法验证的结果只解释并停止，不自动创建、改名、提权、安装、删除或放宽规则。

仅“明确未启动或已退出、临时资源错误、原文件状态未变”的只读任务允许一次修复候选。候选仍使用原始需求、计划、时间界限和阶段 2 参数规则，重新对照需求、审查路径、展示并取得完整 `yes` 确认，再只执行失败的当前步骤。由于参数规则固定，首版修复是原范围内的一次安全重试，不修改系统环境。

整项任务只有一次执行后修复预算；候选拒绝、取消和第二次失败都会停止，不重放已完成步骤。模型格式修正与这个预算分开。修复不得突破原任务总时限；非交互 JSON 和批处理不会默许修复。

写操作失败时只检查实际源、目标和已完成项，记录可能的部分修改或未知状态，不重放任务。历史保留初始失败、程序分类和检查建议、修复候选、授权和最终验证；不能以最后成功覆盖原始失败。写操作预览的源与目标来自准备完成的清单，包括防覆盖后的实际名称，不使用模型说明宣称最终路径。执行前预检能够阻止已知缺失源文件的任务，但不提供执行中途失败的事务回滚保证。

## 受限 ReAct Agent

```bash
python cli.py --agent --timeout 180 "先查找当前目录这一层的 *.txt 文件。数量等于 0 时创建空文件 empty.txt，数量大于 0 时把查到的全部文件复制到 backup。"
python cli.py --agent "先查找当前目录这一层的 *.log 文件。有匹配时把本次查到的全部文件复制到 archive；没有匹配则不修改。"
```

`--agent` 每轮让模型读取上一轮实际执行并独立验证的观察，然后提出一个下一步动作。程序先独立提取并核对两份用户授权约束，再检查每个动作的条件、文件范围和参数。约束中的分支是允许做什么，不是预先假定已经完成的执行序列。模型声明完成后，程序检查所有实际满足条件的动作均已验证，并重新检查最终写入状态。

首版条件只支持实际查找或计数结果与明确整数比较。文件选择只能来自本任务已验证的 `find_files` 完整结果。模型选择已授权查询引用时，程序可以直接绑定实际清单；如果模型自行填写源文件，必须与清单一致。日志分别保存原始决策和绑定参数。写入前和确认后重新检查原始查询范围与文件状态。复杂条件或未明确参数会追问、拒绝或停止，不猜测。每次写入独立预览并确认；`--yes` 仅跳过只读确认，不能授权写入或修复。原有单任务入口仍拒绝混合命令查询和文件写入计划。

整个 Agent 最多五次工具调用，失败尝试和修复执行也计入；最多一次符合原规则的执行后修复。预算不因下一轮重置。重复操作、拒绝、取消、权限不足、失败、无法验证、状态未知和超时均停止。模型请求、准备检查、执行和最终验证共享总时限；人工输入可阻塞，但返回后超过时限绝不继续执行。

只传必要的已验证观察。只需数量时不发送目录文件名。查找结果需用于写操作时最多向模型提供三十个名称；超过上限停止并要求缩小范围，不静默处理部分文件。明确请求的文本查询最多提供五百字符，输出和文件名均标为不可信数据。程序保留完整审计，不默认把完整文件或配置发送给模型。

批处理不支持 Agent。JSON 模式没有交互授权，写操作或修复会停止。预览只显示第一步，不声称能预测尚未发生的观察。首版不保证任意复杂目标可完成，例如反复改写同一文件会被最终状态检查保守拒绝。

目标输出最多修正一次格式错误；这与执行后修复分别记录。明确的查询引用统一成内部格式，不推断缺失引用。Agent 和中间步骤记录不能通过旧的固定计划历史入口重放；重新执行需明确使用 `--agent`，重新观察和确认。

## 测试与真实模型评测

```bash
python -m pytest -q
python eval/run_eval.py --backend local
python eval/run_eval.py --backend local --execute-safe
python eval/compare.py /path/outside-repo/第一次结果.json /path/outside-repo/第二次结果.json
```

新评测集覆盖条件理解、多步规划、必要追问和范围拒绝。判分先统一工作目录内的路径。实际执行只发生在独立临时目录；操作和参数匹配预期的计划可以执行。写法不同的写入计划，还必须通过只读预览证明写操作顺序、源文件及目标文件清单与预期相同，才允许执行；额外写入不允许。执行后仍用独立文件期望检查任务完成。结果文件带时间和编号，不覆盖旧结果。

指标包括条件理解正确率、计划正确率、必要追问率、范围拒绝率和实际任务完成率。计划匹配与实际完成分别记录。未请求执行时，任务完成率为 `null`（未测量）。请求执行时，用独立文件期望检查任务，未获执行许可或执行失败的计划计为未完成。结果保存脱敏后的原始输出、重试错误和拦截原因。不同评测规则的分数不能直接解释为模型能力变化。

自动测试使用模型替身，验证程序逻辑。它不证明真实 Ollama 的理解或规划能力。真实模型评测需另行运行。历史 Bash 数据集保留作旧版本参考，不再由主评测入口执行。

真实 CLI 验收应在仓库外保留一份结果索引，记录提交 SHA、实际模型、原始输入、澄清回答、确认前的执行预览、最终历史记录及独立文件检查。分别统计功能完成、正确的安全拒绝、取消后无写入及未验证项目；未运行不能计为通过。保留原始失败和终端记录，新版本使用新的证据目录，不覆盖已有评测材料。

这些指标测量模型与程序检查共同组成的规划流程，不是裸模型成绩。评测集新增了缺少复制目标和模糊时间的不同表达；不同数据集版本不能直接比较总分。

独立 A/B/C 入口与旧评测分开：A 直接产生候选；B 先产生计划再产生候选；C 增加独立需求及计划/候选一致性检查。三组共享路径、参数和授权检查，不把公共检查算作 C 的贡献。24 条核心任务、6 条故障修复和4条动态 Agent 使用合成文件与独立结果判分。

```bash
python eval/study.py --output-dir /path/outside-repo/study --variants A B C --strategy basic
python eval/study.py --output-dir /path/outside-repo/study --variants C --strategy structured
python eval/study.py --output-dir /path/outside-repo/study --variants C --strategy fewshot
LOCAL_MODEL=qwen2.5-coder:3b python eval/study.py --output-dir /path/outside-repo/study --variants C --strategy basic
python eval/study_supplementary.py --output-dir /path/outside-repo/study
```

输出目录首次登记固定任务、环境时刻和任务 SHA-256，后续实验复用同一登记。真实实验要求工作区已提交。候选正确性、公共审查、C 检查、写入授权和实际结果分别记录。错误写候选接受率是在最后授权前计算；不符合登记范围的写入不执行。写命令仅转译到受保护的 Python 工具，不宣称执行了 Bash cp/mv。A 的计划指标为不适用。无法自动解释的候选保留原文待核对，不将退出码或模型成功标签当成任务完成。

三种 Prompt 都使用接口必需的 JSON 格式；结构化版本增加明确字段约束，fewshot 再增加不属于测试集的开发示例。这是提示文案比较，不是不同 JSON API 模式的比较。模型比较需先实际部署；没有部署结果不能以替身代替。旧评测默认结果也保存在仓库外。

## 提交和推送前检查

克隆后运行一次 `git config core.hooksPath .githooks`。WSL 还需执行 `chmod +x .githooks/pre-commit .githooks/pre-push`。

提交检查读取暂存区，推送检查读取每个新增提交。也可以手动运行 `python scripts/check_upload.py`；检查全部跟踪文件使用 `python scripts/check_upload.py --tracked`。

仓库只接受源码、测试、合成测试数据、依赖、CI、示例配置和本安装说明。论文、文献、计划、真实结果、日志和个人配置留在仓库外。示例配置只填占位值。检查失败时不提交、不推送。

自动检查不能识别所有敏感信息。仍需按文件名暂存并人工检查改动；不能用跳过钩子的方式绕过检查。
